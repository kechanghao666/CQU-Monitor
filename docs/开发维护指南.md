# 开发维护指南（1.2.8）

本文面向接手本工程的同学，先说明数据如何流动，再说明怎样修改并交付。注释解释设计原因和数据边界，不要求给每行语法重复写中文。

## 1. 从哪里开始阅读

建议阅读顺序：README → 已确认需求与实现边界 → 本文 → 接口约定 → 对应测试。

| 文件 | 主要职责 | 修改时重点核对 |
|---|---|---|
| run_app.py、__main__.py | 打包进程入口、Qt应用、日志、单实例锁 | Windows spawn入口、同一data不能双开 |
| config.py、pulse_settings.py | 默认值、配置校验、控制器表单 | 时窗边界、同一物理总线参数/站号、阈值含0 |
| workers.py | 两电压表/电流表读取、换算、1Hz调度 | 字节序、量程、跳秒不补读、成功失败都发布 |
| pulse_workers.py | 每条控制总线顺序读取两组 | 请求起止包住参数和状态，不假设原子快照 |
| isolated.py | 子进程运行设备、父线程转发IPC | 驱动卡住可请求取消，已完成包不丢失 |
| pulse.py | 原始控制观测、当前接通、有效窗判定 | 同通道同周期、递减、前后不同观测、完整请求夹持 |
| engine.py | 纯统计、质量、报警 | 最新值替换、全部有效均值、部分总压、功率单位 |
| controller.py | 主线程协调和停止状态机 | 包处理顺序、晚到错误、保存屏障、关闭和导出互斥 |
| storage.py | schema3、事务、异步记录、流式导出 | 事务回滚、有界队列、恢复副本、统一读视图 |
| ui.py、chart_detail.py | 表格、指示灯、五卡、曲线放大 | 只消费结果；故障断线、停止阶段不能被旧连接包覆盖 |
| dialogs.py | 参数、历史查询、后台导出/清空 | 默认取消确认、运行禁止清空、线程退出前不销毁 |
| startup_check.py | 无设备发行依赖和界面检查 | 不访问串口、不生成测量值 |

## 2. 一条电压如何成为小室结果

控制器原始包有group、started、finished、parameters、registers、error；仪表原始包有role、value、started、finished、error。

控制器观测先进入PulseTracker，形成输出起点可能区间。电压请求结束后，Controller暂存它直到取得请求之后的另一条控制观测。PulseTracker.assess返回None表示还能等待后侧证据；返回字典表示已判定。

只有同通道、同周期且倒计时递减的独立观测能证明整个电压请求都处于有效窗口时，Engine才接纳为有效小室样本。跨界、冻结、等待、超时都留下无效记录及证据，不改成零或“沿用当前值再计一次”。

右组本地通道1—15映射16—30室，左右各自判断；总压使用已经取得的每室最新值，因此它是轮询时刻的组合，并非30室同时测量。

## 3. 均值与时间

- 每室均值：本实验全部有效读数的算术均值。默认1Hz，等权有效读数即当前离散采样口径，不是对缺测时间做插值。
- 当前电流：整组单路连续记录；失败或过期时实时电流及实时功率不可用。
- 总压：从首个有效小室起合计最新值，重复测同室只替换。
- 平均总压/平均功率：每个到达的实验整数秒最多加入一次可用值；跳过的秒不补造。反复调用snapshot/render不会增加计数。
- 功率单位：V×A/1000=kW。不要把A再除以1000，也不要重复转换kW。

修改任何口径，应同时更新Engine测试、使用说明、导出元数据中的计算说明，并由使用方确认。

## 4. 停止和关闭的屏障

顺序是：通知读取停止 → 保持界面响应 → 等待读取者退出 → 排空IPC/主队列/pending → 逐项判定末尾电压 → 后台关闭记录器 → 补记保存阶段晚到异常 → 恢复待机/允许新实验。

“正在停止读取”表示仍在等设备循环；“正在保存数据”表示读取已退出，正在做最终事务或异常追溯。不能为了看起来快而提前恢复待机。

request_stop可接收reason。首次异常必须在第一轮收尾和保存线程启动之前冻结根因。保存阶段的新异常不能向已关闭的普通记录器submit，而由独立晚到事件列表补记。SessionStore.record_session_errors在同一事务中写事件并更正状态；事务失败则保留恢复材料并明确报错。

后台只能合并_stop_failure，不能用保存开始时捕获的旧值覆盖主线程新错误。只有保存线程已结束、晚到事件列表为空，才进入_finish_stop。真正无法写入磁盘时保留内存/恢复材料，不能声明数据库已全部保存。

## 5. 数据库和恢复

数据库在安装程序同目录data/measurements.sqlite3，SQLite WAL。events/samples/summaries/control_observations通过session_id关联sessions；完整载荷以严格JSON保存，NaN仅用于图表断点，不写入数据。

QueuedRecorder只有成功事务提交才减pending数量。批次失败后拒绝新提交、冻结在途与排队数据，写恢复材料。记录器恢复和Controller未投递恢复都采用同目录临时文件，flush/fsync完成后replace，重试失败保护上一完整文件。

恢复文件不是已重新入库的记录。接手者应先保全整个data和恢复材料，在副本中核对session_id、重复行、最后成功事务及最终状态，再决定恢复方案；当前没有“一键导回”。不要直接把恢复JSON重复写入正式库。

正在运行时不能只复制SQLite主文件作为备份，需SQLite备份接口或正常停止后复制整个data。清空历史不删除导出、设置、日志和恢复材料，操作前应先导出需要保留的结果。

## 6. 环境、测试和构建

维护需要Windows x64、Python3.11 x64。将源码包和离线构建依赖包解压到同一个源码目录，检查wheelhouse和tools可见。bootstrap.ps1支持-BasePython，不依赖原作者个人路径。

scripts/verify.ps1依次检查pip依赖、Ruff规则和格式、全套pytest、无设备启动，证据进入artifacts/verify_时间戳。完整隔离进程夹具可运行“.venv/Scripts/python.exe tests/run_pipeline_trial.py”，默认输出到带时间戳的artifacts目录，约运行54秒（实验时间210秒），不会打开实际串口。测试仅在临时目录使用夹具；如需真实设备测试，先另设数据目录并由操作者确认接线和现场安全流程。

scripts/build_release.ps1读取__init__.py版本，构建程序、收集完整许可、编译Inno安装包、提取并复核运行。正常构建只读取随包许可，fetch_license_sources.py仅依赖升级时人工维护使用，可能访问上游网络。

依赖变更应同步requirements.in/lock、离线wheel、来源及许可清单。PySide6的Qt DLL按随包Qt维护说明替换，不能随机复制系统DLL。安装包目标是Windows10 1809+/11 x64，并未支持Win7/8、32位或ARM。

## 7. 常见修改位置

- 改默认端口：config.py；界面显示取实际配置，不在ui硬编码新端口。
- 改阈值：SettingsDialog和Engine；None表示未启用，0是有效阈值。
- 改有效窗口：config校验、PulseTracker和人工Engine路径需一致；控制器端仍手动设相同输出时长。
- 改仪表型号/量程：workers解码及协议配置，先对照真实原始帧和仪表屏幕，不因RS485接口相同就假设寄存器相同。
- 改曲线：ui/chart_detail只改显示，保留有界缓存和故障断点，不参与累计计算。
- 改存储：增加迁移和回归，先复制正式data，禁止直接对用户数据试清空。

## 8. 交付核对

先验证，再构建，再检查安装/卸载/升级的数据保留和包内逐文件一致性。源码、安装包和报告必须对应当前版本。向对方发送正式软件交付包.zip；本机正式软件/data是用户数据，默认不打入发送包。

交付应包含安装包、使用说明、用户确认的Word方案、当前源码、离线依赖、需求核对与现场验收表、完整许可及精简验收证据。旧版安装包、.venv、build、测试数据库、失败试验目录和重复压缩包不混入最终源码包。

真实串口协议、30路线路对应、实际输出/缓存延迟、目标电脑及真实24小时运行，需要现场验收；软件回归和虚拟时间测试不等于这些项目已经完成。


## 声光通知维护
alerts.py只处理提示，不参与统计或硬件控制。报警key决定一次发生/恢复周期；确认集合仅覆盖当前报警。QDialog非模态，PlaySound异步且每3秒触发，停止/重开清理定时器。assets/alarm.wav必须通过build_release.ps1的add-data携带，startup_check校验WAV可读。


## 1.2.6 报警间隔与窗口释放（2026-10-18）

- 报警窗口顶部固定为“请检查设备和测量数值”，唯一按钮为“确认”。确认或关闭弹窗会消音并隐藏提示；采集、显示和记录继续，仍可从顶部报警入口查看。音频播放失败的诊断列在详细信息中。
- 输出结束至下一条状态、正常换路的首次确认、路间和周期间等待均不报警；这些阶段也不延长电压有效窗口或显示可靠接通灯。真实读取失败、参数错误、冻结、倒计时不相容、通信超时仍报警。
- 首次启动允许最多3秒等待第一条控制状态；已收到的明确错误立即提示。开始通信后超过0.6秒没有新控制状态，或换路状态持续超过0.6秒仍无法确认，按异常处理。
- 修复参数窗口关闭后Qt信号闭包保留控件的累积：确认、取消、标题栏关闭以及保存失败均在返回后销毁窗口。实时曲线、日志、控制状态仍采用有界缓存；完整样本在SQLite。

## 1.2.8 本轮复核（2026-10-18）

- 补齐仪表无响应监测：真实采集开始后三秒仍没有任何读取结果会报警；之后默认超过2.5秒没有读取完成包会报警。仪表读取超时配置较长时，监测上限取max(2.5秒, 配置超时+1.5秒)，以免合法请求未完成便误判。电流读数可用性仍独立遵守2.5秒规则。
- 无响应时对应COM卡显示“连接断开”，旧电压保留并标记质量；未收到新电流时当前电流和功率不可用。只有取得真实读取包才恢复响应状态；不生成缺测样本，不自动控制现场装置。
- 读取失败与无响应合并为同一设备报警，避免重复记账。正常采样窗口外的读取同样可以证明通信响应。
- 控制器正常等待仍不报警，但其读取跨度超过0.2秒属于通信异常，不能被“正常间隔”分支掩盖。
- 新增初次请求阻塞、运行中静默、合法长超时和历史入口重复关闭的回归验证；原始停止屏障、有效窗口和计算口径保持不变。

- 1.2.8导出复核：控制记录除原始寄存器外，显式保留interval_remaining及cycle_remaining，路间/周期间倒计时列可直接查看。
