# 代码导读与维护检查（1.2.8）

本工程使用Python 3.11、PySide6/pyqtgraph、PyModbus 2.5.3和SQLite。注释解释时间证据、数据流和退出顺序；英文标识用于接口稳定性，不必把每行Python语法重复翻译为中文。

## 时间证据与统计

设备回包由隔离进程送到有界Queue。Qt主线程先把控制观测放入每组150条的历史，再暂存电压直到取得请求之后的新观测。倒计时量化与整个读取跨度共同形成输出起点区间[L,H]。对电压请求[S,F]，所有可能相位为[S-H,F-L]；只有它全部处于设定有效窗口，且同通道、同周期、递减且新鲜，才可接纳。无法确认时保存无效原因，不放宽边界。

healthy/alarm与active独立：正常间隔可以通信健康、无需报警，同时不能证明输出接通。修改报警不能把正常间隔延长为采样窗口。

每室均值使用递推计数，不存整段历史；总压使用每室最新值。每个到达的实验整数秒最多统计一次汇总，snapshot/render不修改累计量。完整明细进入SQLite，界面只保留有界尾部。

## 生命周期与失败处理

开始只在待机且保存安全时建立新会话。停止必须按读取退出→主队列/pending排空→逐包判定电压→最终快照→后台记录器关闭→晚到错误补记→待机的顺序执行。生产界面不能调用阻塞式join等待各串口。关闭窗口也要经过同一保存屏障及导出结束。

写库只有事务成功才减少pending计数。失败时停止继续生产，保留原始载荷及恢复材料；恢复临时文件flush/fsync后原子替换，写失败保护上一完整文件。恢复I/O不持共享状态锁。没有自动恢复导回，人工操作须在数据库副本中核对重复与最后提交。

Qt设置窗口返回前读取values，finally中deleteLater，防止闭包保留隐藏控件。放大窗口共享主图缓存；历史后台任务完成前禁止销毁窗口。

## 可重跑命令

推荐把源码和离线依赖解压到较短路径，例如C:\CQU\src，避免Windows长路径影响依赖恢复或PyInstaller。先装Python 3.11 x64，再从该目录执行：

```powershell
.\scripts\bootstrap.ps1 -BasePython 'C:\Python311\python.exe'
.\scripts\verify.ps1
.\.venv\Scripts\python.exe tests\run_pipeline_trial.py --output artifacts\pipeline
.\.venv\Scripts\python.exe tests\run_memory_trial.py --seconds 1200 --output artifacts\memory
.\.venv\Scripts\python.exe tests\analyze_memory_trial.py --output artifacts\memory
.\scripts\build_release.ps1
```

Python路径为示例，替换为本机解释器。输出目录必须未存在，防止不同实验记录混合。夹具会阻止真实串口，使用临时数据库；曲线预填压力点不写入正式样本库，内存测试中的声音为计数替身。物理声音须现场另验。

scripts/verify_installation.py用于沙盒新安装、覆盖升级、卸载保留数据及正式目录升级，必须显式提供安装包、构建bundle、--formal-dir正式目录和输出目录。它会进行当前用户安装注册，最后升级正式目录以恢复登记；须完整运行本机验收，避免把正式登记留在临时测试目录。命令和退出报告以该脚本--help为准。测试不能替代干净Windows验收。

## 构建、许可和交付

build_release.ps1读取__init__.py的版本，冻结生产入口，检查未使用Qt模块未混入，收集完整许可和对应源码，编译Inno安装包，提取后再次启动核对。packaging/hooks只裁减未使用的Qt插件，不改动上游运行库代码。

packaging/corresponding-source内三个完整6.8.3源包包含QtBase、QtSvg、PySide及Shiboken；SOURCES.json记录URL、版本和SHA256。fetch_license_sources.py仅维护升级时联网取得固定版本源包，正常构建离线完成。升级依赖需同步requirements、wheelhouse、源码版本、许可和运行验证，不能只替换DLL。

scripts/render_user_guide.py从docs/使用说明.md生成离线HTML；编辑说明后执行一次并核对页面文字。scripts/read_database_evidence.py只读检查数据库完整性和各表指纹。

发行包保留源码/离线依赖/原始参考资料/用户Word/当前验收证据；不发送用户data或测试数据库。软件侧结论、夹具、本机安装、目标电脑和真实24小时证据分别标识。完整测试通过不等于已证明零缺陷。


## 1.2.8 本轮复核（2026-10-18）

- 补齐仪表无响应监测：真实采集开始后三秒仍没有任何读取结果会报警；之后默认超过2.5秒没有读取完成包会报警。仪表读取超时配置较长时，监测上限取max(2.5秒, 配置超时+1.5秒)，以免合法请求未完成便误判。电流读数可用性仍独立遵守2.5秒规则。
- 无响应时对应COM卡显示“连接断开”，旧电压保留并标记质量；未收到新电流时当前电流和功率不可用。只有取得真实读取包才恢复响应状态；不生成缺测样本，不自动控制现场装置。
- 读取失败与无响应合并为同一设备报警，避免重复记账。正常采样窗口外的读取同样可以证明通信响应。
- 控制器正常等待仍不报警，但其读取跨度超过0.2秒属于通信异常，不能被“正常间隔”分支掩盖。
- 新增初次请求阻塞、运行中静默、合法长超时和历史入口重复关闭的回归验证；原始停止屏障、有效窗口和计算口径保持不变。

- 1.2.8导出复核：控制记录除原始寄存器外，显式保留interval_remaining及cycle_remaining，路间/周期间倒计时列可直接查看。
