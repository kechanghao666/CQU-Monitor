# 当前维护接口（1.2.8，2026-10-18）

最新业务约束见《已确认需求与实现边界.md》。以下取代首版固定时序与单纯读取线程模型。

## 主模块
- config.py：default_settings/load/save/validate_settings。validate_timing统一校验输出与窗口，返回width/start/end；全配置仅hardware，含synchronization=controller/manual、两组controllers、三仪表ports及报警阈值。
- workers.py：纯仪表解码、单调时钟、锚定1Hz、SerialProducer；pulse_workers.py：同控制器物理串口顺序读取FC03/04的11/4与22/6。
- isolated.py：IsolatedProducer(worker_type,args,output,clock,stop_event,name)，真实读取循环在spawn子进程；监控线程将完整管道消息传回主Queue。属性pending/failure/forced_stop/process；schedule_origin共享人工同步时间。run_app冻结入口先freeze_support再加载Qt。
- pulse.py：PulseTracker(profiles,settings)，ingest原始参数/状态及整个请求起止；snapshot可靠接通状态；assess(group,started,finished,now,final)给出valid/status/cell/phase_min/max/before/after等证据，非final可暂返None，final必须可结算或留为无效。
- engine.py：Engine(config,session_id)，start/reset、人工synchronize、accept、tick、snapshot；set_controller_health及set_controller_intervals分别更新组健康与新鲜度。控制器模式accept必须核对sync_context对应同一请求与组别、窗口。

## 数据契约
所有载荷为严格JSON可表达字典，缺测None，禁止NaN污染数据库。角色voltage_left/voltage_right/current；ISO时间带时区，elapsed为本实验秒。
- 样本：session_id,role,cell,round,phase,elapsed,wall_time,value,valid,status,error,mean_value,sync_version,synchronization_source,sync_evidence。
- 汇总：session_id,elapsed,wall_time,total_voltage,avg_total_voltage,current,power_kw,avg_power_kw,complete,reason,measured_count,available_count,coverage,quality。
- 核心快照：session_id,mode,elapsed,synchronized,sync_version,slot,round,phase,cell_pair,cells,metrics,alarms,synchronization_source；Controller在控制器模式追加controllers，替换活动cell_pair及synchronized。
- cell：cell,latest,mean,count,updated_at,age,status。控制观测保留group/sequence/channel/remaining/width/outputs/cycle/stage/status/error/valid及原始寄存器/请求起止。

## 控制器和停止
Controller为Qt主线程状态机：start，request_stop，request_shutdown，poll，drain，flush_pending，capture_snapshot，configure，export，history。
request_stop是生产界面异步入口，stop仅供离线脚本在无活跃读取者时等待收尾兼容；生产不能调用join等待多个串口阻塞界面。
停止：关闭生产意图→仍可响应Qt事件→全部读取者退出→排空output和各worker.pending→逐条final电压→最终快照→后台recorder.close/未投递恢复→finish待机或安全关闭。读取者活跃、队列未空或写库未完不得重开。
单包处理故障需保留raw_packet诊断恢复并继续后续正常包；显示故障不得阻断原样本入库；停止末尾新错误也需事件入库和error状态。

## 持久化与导出
SessionStore(db_path)：create_session/write_batch/finish_session/list/get/query_samples/query_summaries/query_controls/export_session/export_snapshot/clear_history；schema3，SQLite WAL，操作各自连接。查询分页，历史导出共用一次读取视图；跨时区按实际时刻比较。
QueuedRecorder：有界提交队列、批量写库，只有成功提交才减pending_count；close必须在生产者及尾包处理后，失败保留未提交载荷和最终快照。恢复写盘由独立锁串行，不持共享状态锁；同目录临时写完、fsync、replace，失败保留旧完整文件和内存。
历史清空事务先拒绝running会话，删除子表再父表，任何错误回滚。UI额外禁止采集/导出/收尾中操作且默认取消确认。
当前页导出是原始会话参数+30室快照+底部指标；历史导出是筛选样本/每秒汇总/控制器/事件，并附该会话最终或最新快照（该附表不随筛选重算）。

## 界面
MainWindow信号：start_requested/stop_requested/sync_requested/settings_requested/export_requested/history_requested/close_requested；set_running/set_stopping/set_saving/render/set_devices/reset_session/add_sample/add_summary。
SettingsDialog.values应用到下一次实验，当前已停止快照不改算。HistoryDialog后台导出/清空，history_cleared通知Controller清空停止快照与主页面。TrendChart缓存有界、异常缺测断点，ChartDetail共享缓存更新，不另行采样或计算。

1.2.4异常追溯补充：request_stop(status, reason=None)在首次收尾前冻结根因；保存阶段新错误进入_late_stop_events，记录器结束后用SessionStore.record_session_errors原子写事件及error状态，清空晚到列表后才待机。后台只合并错误；补记失败写独立原子恢复材料。


## 1.2.5 报警通知与实时显示

- 新出现的超限、仪表断线/过期、控制器状态异常弹出非模态报警窗口，同时播放随软件附带的提示音；未确认时每3秒重复一次。
- 多条报警合并在同一窗口。同一持续报警不反复弹窗；确认按钮或关闭弹窗均停止当前声音，但不修改故障判定，也不停止采集。顶部“报警”按钮可重新查看。
- 所有报警恢复后提示关闭；恢复后再次出现或新增其他报警会重新提醒。停止采集后消音，停止前报警仍可查看；新实验重新开始报警判定。
- 电流超限后出现断线或过期，只记录“状态无法判定”，不能把缺测当成恢复正常。
- 声音采用Windows异步PlaySound及内置WAV，不阻塞Qt事件循环；需要电脑有可用扬声器且音量未静音，软件不能保证物理扬声器实际发声。
- 弹窗打开时，最新有效电压、电流、累计均值、部分总压和功率仍实时更新。电流失效时实时电流和功率留空；旧电压保留并提示质量；无效区间不计入电压结果。


## 1.2.6 报警间隔与窗口释放（2026-10-18）

- 报警窗口顶部固定为“请检查设备和测量数值”，唯一按钮为“确认”。确认或关闭弹窗会消音并隐藏提示；采集、显示和记录继续，仍可从顶部报警入口查看。音频播放失败的诊断列在详细信息中。
- 输出结束至下一条状态、正常换路的首次确认、路间和周期间等待均不报警；这些阶段也不延长电压有效窗口或显示可靠接通灯。真实读取失败、参数错误、冻结、倒计时不相容、通信超时仍报警。
- 首次启动允许最多3秒等待第一条控制状态；已收到的明确错误立即提示。开始通信后超过0.6秒没有新控制状态，或换路状态持续超过0.6秒仍无法确认，按异常处理。
- 修复参数窗口关闭后Qt信号闭包保留控件的累积：确认、取消、标题栏关闭以及保存失败均在返回后销毁窗口。实时曲线、日志、控制状态仍采用有界缓存；完整样本在SQLite。

PulseTracker.snapshot的healthy/alarm与active分开：healthy表示当前通信和时序未发现报警条件；active仍要求新鲜且连续确认的输出证明。boundary_wait、短暂transition/unconfirmed及新鲜waiting为正常状态，不能触发voltage_quality；所有电压assess边界和前后观测校验不变。长时间等待也必须持续取得新控制状态，否则stale。
Controller.configure在finally执行deleteLater，先读取accepted窗口中的参数再销毁；不得给可读取values的模态设置窗口提前启用DeleteOnClose。

## 1.2.8 本轮复核（2026-10-18）

- 补齐仪表无响应监测：真实采集开始后三秒仍没有任何读取结果会报警；之后默认超过2.5秒没有读取完成包会报警。仪表读取超时配置较长时，监测上限取max(2.5秒, 配置超时+1.5秒)，以免合法请求未完成便误判。电流读数可用性仍独立遵守2.5秒规则。
- 无响应时对应COM卡显示“连接断开”，旧电压保留并标记质量；未收到新电流时当前电流和功率不可用。只有取得真实读取包才恢复响应状态；不生成缺测样本，不自动控制现场装置。
- 读取失败与无响应合并为同一设备报警，避免重复记账。正常采样窗口外的读取同样可以证明通信响应。
- 控制器正常等待仍不报警，但其读取跨度超过0.2秒属于通信异常，不能被“正常间隔”分支掩盖。
- 新增初次请求阻塞、运行中静默、合法长超时和历史入口重复关闭的回归验证；原始停止屏障、有效窗口和计算口径保持不变。

- 1.2.8导出复核：控制记录除原始寄存器外，显式保留interval_remaining及cycle_remaining，路间/周期间倒计时列可直接查看。

Engine.set_meter_responsive(role, responsive)只更新无回包质量，保留上次真实请求健康与原数值；Controller使用实际读取完成包监测，停止阶段冻结该状态。
