# 重庆大学电解水制氢系统 1.2.8

本工程用于30小室电压、整组电流的只读采集、计算、显示和记录。正式应用不含模拟模式，启动只显示待机界面，点击开始后才连接设备。

## 建立环境与验证

在源码目录打开PowerShell，使用64位Python 3.11：

```powershell
# 可自动查找py -3.11；也可显式指定已安装的基础Python路径。
.\scripts\bootstrap.ps1 -BasePython 'C:\Python311\python.exe'
.\scripts\verify.ps1
.\.venv\Scripts\python.exe tests\run_pipeline_trial.py
.\scripts\run.ps1
```

上面的Python路径是示例，替换为本机实际路径。已有正确的Python启动器时可直接运行bootstrap.ps1，不传参数。离线目录存在时只从wheelhouse安装锁定版本；恢复后先确认全部测试通过，再修改代码。

## 构建安装包

```powershell
.\scripts\build_release.ps1
```

构建脚本从cqu_monitor/__init__.py读取版本，生成release/CQU-Monitor及release/installer下的安装包，并核验冻结程序、安装包提取程序的无设备启动。工具固定在tools目录，正常构建不需要下载许可文件。改变依赖版本时应同步更新锁定文件、wheelhouse与许可来源，不直接替换某个DLL。

## 数据流和职责

1. workers.py/pulse_workers.py执行仪表与控制器的只读请求；isolated.py把它们放在子进程，主进程转发完整结果。
2. controller.py在Qt主线程按顺序接收包；pulse.py用请求前后的独立控制观测判断当前小室及有效窗口。
3. engine.py只做计算：有效样本均值、部分总压、电流、功率和每秒累计。
4. storage.py的QueuedRecorder后台事务写SQLite；UI和导出读取已经形成的快照，不改变统计。
5. ui.py负责五路COM状态、30个小室指示灯和33张可筛选/放大的图；dialogs.py负责参数及历史管理。

完整约定见docs/接口约定.md；数据口径和现场边界见docs/已确认需求与实现边界.md。

## 修改时必须保持的规则

- 有效电压要求完整请求及其不确定性均在设定窗口，不凭最近一次通道猜测；没有可靠证据就保存无效原因，不补造数。
- 未测齐也立即合计每室最新值；每室累计均值只计本实验全部有效读数。总压和功率的累计均值按到达的整数秒统计，刷新界面不重复计数。
- 点击停止后先退出读取者、排空队列和尾包，再保存。晚到异常须补记历史并标记error，错误信息不能被后台旧结果覆盖。
- 保存失败必须明确显示，未提交材料采用临时文件写完后替换；恢复文件需人工核对，不自动导回。
- 新增核心规则先写能复现问题的测试，确认失败再实现；修改后执行全套验证及安装包启动检查。
- 不写控制器寄存器，不把停止采集解释成设备急停或阀门关闭。

## 1.2.5 报警通知与实时显示

- 新出现的超限、仪表断线/过期、控制器状态异常弹出非模态报警窗口，同时播放随软件附带的提示音；未确认时每3秒重复一次。
- 多条报警合并在同一窗口。同一持续报警不反复弹窗；确认按钮或关闭弹窗均停止当前声音，但不修改故障判定，也不停止采集。顶部“报警”按钮可重新查看。
- 所有报警恢复后提示关闭；恢复后再次出现或新增其他报警会重新提醒。停止采集后消音，停止前报警仍可查看；新实验重新开始报警判定。
- 电流超限后出现断线或过期，只记录“状态无法判定”，不能把缺测当成恢复正常。
- 声音采用Windows异步PlaySound及内置WAV，不阻塞Qt事件循环；需要电脑有可用扬声器且音量未静音，软件不能保证物理扬声器实际发声。
- 弹窗打开时，最新有效电压、电流、累计均值、部分总压和功率仍实时更新。电流失效时实时电流和功率留空；旧电压保留并提示质量；无效区间不计入电压结果。


## 1.2.6 报警间隔与窗口释放（2026-10-18）

- 报警窗口顶部固定为“请检查设备和测量数值”，唯一按钮为“确认”。确认或关闭弹窗会消音并隐藏提示；采集、显示和记录继续，仍可从顶部报警入口查看。音频播放失败的诊断列在详细信息中。
- 输出结束至下一条状态、正常换路的首次确认、路间和周期间等待均不报警；这些阶段也不延长电压有效窗口或显示可靠接通灯。真实读取失败、参数错误、冻结、倒计时不相容、通信超时仍报警。
- 首次启动允许最多3秒等待第一条控制状态；已收到的明确错误立即提示。开始通信后超过0.6秒没有新控制状态，或换路状态持续超过0.6秒仍无法确认，按异常处理。
- 修复参数窗口关闭后Qt信号闭包保留控件的累积：确认、取消、标题栏关闭以及保存失败均在返回后销毁窗口。实时曲线、日志、控制状态仍采用有界缓存；完整样本在SQLite。

## 1.2.8 本轮复核（2026-10-18）

- 补齐仪表无响应监测：真实采集开始后三秒仍没有任何读取结果会报警；之后默认超过2.5秒没有读取完成包会报警。仪表读取超时配置较长时，监测上限取max(2.5秒, 配置超时+1.5秒)，以免合法请求未完成便误判。电流读数可用性仍独立遵守2.5秒规则。
- 无响应时对应COM卡显示“连接断开”，旧电压保留并标记质量；未收到新电流时当前电流和功率不可用。只有取得真实读取包才恢复响应状态；不生成缺测样本，不自动控制现场装置。
- 读取失败与无响应合并为同一设备报警，避免重复记账。正常采样窗口外的读取同样可以证明通信响应。
- 控制器正常等待仍不报警，但其读取跨度超过0.2秒属于通信异常，不能被“正常间隔”分支掩盖。
- 新增初次请求阻塞、运行中静默、合法长超时和历史入口重复关闭的回归验证；原始停止屏障、有效窗口和计算口径保持不变。

- 1.2.8导出复核：控制记录除原始寄存器外，显式保留interval_remaining及cycle_remaining，路间/周期间倒计时列可直接查看。
